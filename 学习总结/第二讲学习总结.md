## 一句话总结

2017 年的 Transformer 骨架至今没变，但现代 LLM（GPT、DeepSeek、Qwen、Llama…）几乎全是 **decoder-only** 形态——它们只保留原版的「一半」，**换掉了三个部件**（位置→RoPE、归一化→RMSNorm、注意力→滑动窗口+GQA），然后靠 **Scaling Laws + MoE** 把规模做大，靠 **解码策略 + 提示词** 把它用起来。

## ① 模型家族：同一台 Transformer 的三支后代

原版 Transformer 是「encoder + decoder」双塔，为机器翻译设计。把两半拆开用，长出三支：

| 家族 | 留下哪半 | 注意力方向 | 擅长 | 代表 |
|---|---|---|---|---|
| **encoder-decoder** | 两半都留 | 双向 + 交叉 | 翻译、摘要（文本→文本） | T5、mT5、ByT5 |
| **encoder-only** | 只留 encoder | **双向**（同时看左右） | 理解、分类、编码 | BERT、DistilBERT、RoBERTa |
| **decoder-only** | 只留 decoder | **因果/单向**（只看自己和左侧） | 生成（逐 token 往后写） | GPT 一系，**现代 LLM 主流** |

**为什么最后是 decoder-only 胜出**：同样算力投在 decoder 上最划算；训练目标「next-token prediction」最简单、最容易放大和泛化，而且「接着往下写」和今天的聊天应用天然对齐。去掉 encoder 后，cross-attention 也随之消失，每个 block 只剩 masked self-attention + FFN。

> BERT 的「bidirectional」是重点：encoder 的 self-attention 没有 mask，每个 token 能同时看左右两侧；GPT 用 causal mask，只能看自己和前面。这是两者最根本的分野。

## ② 缩放定律（Scaling Laws）：为什么要「大」

- **Kaplan et al., 2020**：模型越大、数据越多、算力越多，性能就越好，而且关系是**可预测的**；大模型还更「省样本」（sample efficient）。
- **Chinchilla (Hoffmann et al., 2022)**：给定固定算力预算，模型规模和训练数据要按比例配——大约是**每 1 个参数配 20 个 token**。结论从「堆参数」转向「参数和数据一起堆，别顾此失彼」。
- **LLM 的定义**：在「参数（≥10B 量级）、数据（数千亿~数万亿 token）、算力（一批 GPU）」三个维度一起放大的 decoder-only 语言模型。BERT 是 encoder-only、不生成文本，按现在的口径**不算 LLM**。

> ⚠️ **FLOPs vs FLOPS（老师特意强调，别搞混）**：`FLOPs`（小写 s）= Floating Point **Operations**，衡量**算力总量/计算量**，越大算力越强（LLM 训练量级约 10²⁵ FLOPs）；`FLOPS`（大写 S，常写作 FLOPS/s）= **算速**，衡量硬件每秒能做多少次浮点运算。前者是「总共做了多少」，后者是「每秒能做多少」。

## ③ 专家路由（MoE）：参数变大，每个 token 的计算量不变

**动机**：几千亿参数若每个 token 都全量前向，太贵。MoE 的想法是「屋里坐着数学家、物理学家、化学家、历史学家，一道数学题不需要四个人都答」。

- **做法**：把每层参数最多的 FFN，换成「**一个 router（门控）+ 一组 N 个 expert FFN**」。router 看输入给每个 expert 打分，只让 top-k 个（k 常取 1 或 2）真正计算，输出按权重加权求和。
- **dense vs sparse**：dense MoE 所有 expert 都算（不省）；**sparse MoE 只算 top-k**（这才是省）。衡量计算用 FLOPs。
- **关键：总参数 vs active 参数**。expert 越多总参数越大（模型容量大），但每个 token 只走 k 个 expert，**active 参数基本不变**——这就是 MoE 能做到万亿参数的原因。例：Mixtral 8x7B = 47B 总参数 / 13B active（8 个 expert，每 token 选 2 个）。
- **训练难题 routing collapse**：router 可能「偷懒」总选同一两个 expert，其余白占参数。解法：加一个**负载均衡辅助损失**（把各 expert 的使用比例和平均概率都推向均匀）；另有 noisy gating（给打分加噪声）。
- **趋势**：共享专家（所有 token 都过的基础专家）+ 细粒度专家（更多、更小的专家）。

## ④ 架构优化：原版换掉的三个部件

这是 2025 版第 2 讲的主体，也是「从 Transformer 到现代 LLM 之间发生了什么」的答案。

### 4.1 位置编码：从「加一个向量」到「转一个角度」

注意力天生分不清顺序（「狗咬人」和「人咬狗」在它眼里是一包 token）。位置信息注入方式的演进：

| 做法 | 放在哪 | 怎么算 | 短板 |
|---|---|---|---|
| learned embedding | 加到 token 向量上 | 每个位置学一个向量 | 依赖训练集偏差；超长位置没学过 |
| sinusoidal（写死） | 加到 token 向量上 | 不同频率 sin/cos 公式 | 加在输入上太间接 |
| T5 bias | attention 分数上 | 相对距离分桶，每桶学一个 bias | 学出来的，依赖训练分布 |
| ALiBi | attention 分数上 | 距离 × 固定斜率，不学习 | 形式太简单 |
| **RoPE** ✅ | **attention 里的 q、k** | **按位置把 q、k 各转一个角度** | 今天的默认选择 |

> 🕐 **为什么 sinusoidal 要用「不同频率」？——手表指针类比（老师原话）**：手表有时针、分针、秒针，三根针各自以**不同频率**转动——时针最慢（只能粗略定位「在一天的哪个时段」）、分针快些、秒针最快（最精确）。**三根针合在一起，你才知道确切时间**。位置编码同理：用一组**从低频到高频**的 sin/cos，每个维度就是一根「不同转速的指针」，合在一个向量里，模型就能判断自己「精确在第几个位置」。

**RoPE（Rotary Position Embedding, RoFormer/Su et al. 2021）**：把位置 m 的 query 旋转一个和 m 成正比的角度、位置 n 的 key 旋转和 n 成正比的角度，再点积。两次旋转合并成一次，**打分只含相对距离 (n−m)**，还带**长程衰减**（相距越远打分上界越低）。不学参数、不限于训练长度、形式又不像 ALiBi 那么死。LLaMA、Qwen、Mistral、DeepSeek 全用它；后来的长上下文扩展（position interpolation、YaRN）都是在缩放这些角度。

### 4.2 归一化：post-norm LayerNorm → pre-norm RMSNorm

- **原版**：`Norm(x + Sublayer(x))`（post-norm，LayerNorm 减均值除标准差、学 γ 和 β）。
- **今天**：`x + Sublayer(Norm(x))`（pre-norm，残差支路不被归一化打断、深层梯度更稳），且 LayerNorm 换成 **RMSNorm**（不减均值、只除均方根、只学 γ）——效果相当但参数更少、更快。

### 4.3 注意力效率：滑动窗口 + 共享 K/V（GQA/MQA）

注意力是 O(n²)，序列一长就吃不消。两种省法：

- **滑动窗口（sliding window / local attention）**：每个 token 只看自己邻域，交互矩阵从满的 n×n 变成对角线附近一条带。配合「局部层与全局层交替」保留长程信息；多层堆叠后感受野逐层扩大（Mistral 每层都是 sliding window）。
- **共享 K/V 投影**：Q 保持每头一套，K、V 让多个头共用，**目的是缩小 KV cache**（解码时要把已生成 token 的 K、V 存起来复用，头数越少缓存越小）。

| 方案 | K/V 共享程度 | KV cache |
|---|---|---|
| MHA（原版） | 每头一套 | 最大 |
| **GQA** | 分 g 组共享 | 折中，**近年最常见** |
| MQA | 全部共享（1 套） | 最小 |

> 为什么共享的是 K、V 而不是 Q：Q 是「发问」，保留多问法有好处；而且 **Q 从不被缓存**（每次只算当前 token 的 Q、用完即弃），共享它没有意义。K、V 才是在生成时被一遍遍复用、要存进显存的东西。

## ⑤ 解码策略与提示词：怎么生成、怎么问

### 5.1 解码策略（怎么从概率分布里取下一个词）

生成是一个循环：给定当前序列 → 输出「下一个 token 的词表概率分布」→ 选一个接到末尾 → 再喂回去，直到 EOS。「怎么选」就是解码策略：

| 策略 | 做法 | 特点 |
|---|---|---|
| greedy | 每步取概率最大 | 确定、无多样性；每步最优≠整句最优 |
| beam search | 同时保留 K 条最优路径 | 适合翻译；仍缺多样性，LLM 对话一般不用 |
| sampling | 按概率随机抽 | 有多样性；配合截断用 |
| top-k | 只在概率最高的 k 个里抽 | 截掉尾部噪声 |
| top-p（nucleus） | 累计概率刚过 p 的最小集合里抽 | 候选数随分布自动伸缩 |
| **temperature** | logit 除以 T 再过 softmax | T→0 变贪心，T→∞ 变均匀，T 大更「随机」 |

**确定性（T=0 也未必完全确定）**：随机性只来自采样，`T=0` 理论上应该完全确定。但实践里推理引擎会把你的请求**和其他请求 batch 在一起**，非确定性就来自这里——根因是**浮点加法的非结合性（non-associativity）**：加法顺序一变，结果就变。例：`大数 + 小数 − 大数` 可能算出 0，但 `(大数 − 大数) + 小数` 却能得到那个小数。因为 batch 内容不同 → 求和顺序不同 → 结果漂移（即 **batch invariance 被破坏**）。Horace He 有篇博客专门讲这个，以及如何写 kernel 保持 batch invariance。

**guided decoding（引导解码 / 生成结构化输出）**：工业里常要 LLM 输出**结构化数据（如 JSON）**。直接 prompt「请输出 JSON」今天的模型大多能行，但不是 100%。**guided decoding** 的做法是：按目标语言的**语法**，在每一步**限制可预测的 token 集合**——比如 JSON 里第一个 token 必须是 `{`、字段名后必须接 `:`。这样从机制上保证输出合法、下游解析不会失败。

### 5.2 提示词：不改权重就改善回答

- **context rot（上下文「腐烂」）**：上下文不是越长越好。有个著名测试叫 **needle in a haystack（大海捞针）**——把一段关键信息藏在上下文窗口某处，任务是把它检索出来；结果**上下文越长，模型越难捞到那根针**（信息被噪声淹没）。所以才有 **context compaction（上下文压缩）**、定期开新对话等实践。
- **in-context learning（ICL）**：在提示里给示例。zero-shot（不给示例）、few-shot（给几个示例）；给示例不一定更好。
- **chain of thought（CoT）**：让模型「先想过程再给答案」，显著提升推理题正确率；延伸有 self-consistency（多采样几次取多数）。
