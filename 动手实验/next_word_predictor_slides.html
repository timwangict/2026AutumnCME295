next_word_predictor.py 一个词怎么一步步变成「下一个词」的预测 vocab = 6 词 · hidden = 2 · seed = 1
STEP 1one-hot

One-hot 编码 · 把词变成网络能读的向量

网络读不了字符串 "cute"。于是给词表里 6 个词各分一个槽位（0–5），用一个向量表示一个词：只有自己那一位是 1，其余全是 0。

词表 vocab → 「cute」的 one-hot

cutefluffyteddybearrunsfast
100000
!
这个向量只说「是谁」，别的什么都没有——任意两个不同的 one-hot 向量都一样「不相似」，没有语义可言。要让它有含义，看下一步。
STEP 2embedding

嵌入 = one-hot × W1

W1 是一张 6×2 的权重表（训练中学会）。因为输入是 one-hot，乘法「选中」了 W1 的某一行——那一行，就是这个词的嵌入。

W1 嵌入表（6 × 2）· cute 选中第 0 行

embedding = x @ W1  (1×6) @ (6×2) → (1×2)
逐项展开：one-hot(cute) = [1, 0, 0, 0, 0, 0]，与 W1 每一列做点积（逐项相乘再相加）
dim1 1×0.512+0×0.144+0×0.312+0×0.828+0×0.550+0×0.754 =0.512
dim2 1×0.950+0×0.949+0×0.423+0×0.409+0×0.028+0×0.538 =0.950
0 × 任何数 = 0，5 个「0×」项全部清零 → 只剩 cute 那一行被「1×」保留 → 结果不是算出来的，而是直接取出 W1 的第 0 行 [0.512, 0.950]。这就是「查表」：one-hot 里那个 1 的位置，决定取哪一行。
!
「cute」→ [0.512, 0.950]。为什么是 2 个数而不是 6 个？因为稠密向量能把相近的词放得近（cute 靠近 fluffy），one-hot 永远做不到。
STEP 3scores

打分 = 嵌入 × W2

W2（2×6）把这 2 维嵌入映射回 6 个词，每个词一个「原始分数」（logit）——它还不是概率，可正可负、可大可小。

raw scores（还没归一化）

这次不是「查表」，是真正的点积：embedding 的两个数 [0.512, 0.950] 都非零，所以要逐项相乘再相加；而 step 2 里 one-hot 只有一个 1，才退化成「查表」。W2 里的 0.330、0.203 和 W1 一样，都是 seed=1 抽出的随机数，属于「未训练」的初始权重。
!
此刻 fast 分数最高（1.138），但这是未经处理的原始值。要把它变成「该选谁」的概率，需要最后一步 softmax。
STEP 4softmax

Softmax → 预测下一个词

Softmax 把原始分数压成概率：每个值都为正、加起来正好等于 1，分数越大占比越大。取概率最大的词，就是预测。

现在预测是瞎猜（cute → fast），因为 W1/W2 还是随机权重。训练 = 反复微调 W1、W2，直到「cute」稳定地指向合理的下一个词——这就是 Word2Vec 和一切 LLM 预训练的原型。
