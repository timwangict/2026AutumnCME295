## 一句话总结

**上一讲只讲了"做什么"（RLHF/推理的流程），这一讲讲"损失函数到底怎么来的"。** 核心是一个目标——最大化期望奖励，一个梯度技巧——`∇log π = ∇π/π`（把梯度"塞进"期望），三类挑战——梯度噪声、缺 token 级归因、会跑偏；对应的两套主流解法——**PPO**（用 value function 算 token 级 advantage，但要额外训一个模型）和 **GRPO**（用组内标准化算 advantage，省掉 value model）；以及解决 GRPO「只看最终答案」缺点的升级方案——**on-policy distillation**（用 teacher 模型给 token 级密集信号）。

## 0. 三个"免责声明"（老师反复强调，别踩坑）

1. **符号混乱是常态**：`r` 有时是 reward、有时是 ratio（本课用 ρ 表 ratio）；`π` 有当前 π_θ、旧 π_old、参考 π_ref 三种；`L` 有时是 loss（最小化）、有时是 objective（最大化）。
2. **先直觉、后公式**：大公式别怕，抓"为什么要这个量"。
3. **第一性原理读公式**：每一步都问"它在奖励什么、惩罚什么"。

## 1. RL 基础：怎么映射到 LLM

经典 RL 是 agent（智能体）在 environment（环境）里选 action（动作）、拿 reward（奖励）。映射到 LLM：

| RL 概念 | LLM 对应 |
|---------|----------|
| agent | 语言模型 |
| state（状态） | 输入 prompt |
| action（动作） | 下一个 token（或整个 response） |
| policy π_θ | 模型输出的概率分布 |
| reward | 对"回答好坏"的打分 |

> reward 在 **token 级**很难定义，所以大多在 **response / completion 级**给一个总分。

---

## 2. 两类 reward（上一讲的总结，本讲前提）

- **无 ground truth（主观）**：如语气好坏 → 人类偏好 + **奖励模型**（Bradley-Terry）→ 这叫 **RLHF**。
- **可验证对错（客观）**：数学有标准答案、代码能跑测试 → 确定性判定 → 这叫 **RLVR**（RL with Verifiable Rewards），用于推理。

---

## 3. 核心目标 + Policy Gradient（本讲数学命根子）

**目标**：最大化期望奖励

```
J(θ) = E_{τ ~ π_θ} [ R(τ) ]      （τ = 轨迹，从当前策略采样）
```

**梯度**（policy gradient）：

```
∇J(θ) = E_{τ ~ π_θ} [ R(τ) · ∇log π_θ(τ) ]
```

**推导只用一个恒等式**（务必记住）：

```
∇log π = ∇π / π        （log 的求导规则）
```

于是 `∇π = π · ∇log π`，把 ∇ 从"积分外面"换到了"期望里面"，就能用采样估计梯度。

**直觉**（比公式重要）：
- reward 为正 → 梯度鼓励**提高**该动作的概率；
- reward 为负 → 梯度鼓励**降低**该动作的概率。

因为是**最大化**，所以更新用**梯度上升**：`θ ← θ + α·∇J`（对比预训练/SFT 的梯度下降 `θ − α·∇L`）。

## 4. Importance Sampling Ratio：为什么 on-policy 贵

**问题**：on-policy 每次更新都要让模型**重新生成** response，而生成是自回归的、**串行、无法并行、极贵**。

**区分两个操作**（关键提问，很多人这里懵）：

| 操作 | 是否并行 | 为什么 |
|------|----------|--------|
| **evaluation（评估概率）** | ✅ 并行、便宜 | 完整序列已知，一次性全喂进去，decoder-only 的掩码注意力可同时算所有位置概率 |
| **generation（生成 rollout）** | ❌ 串行、贵 | 必须逐 token 生成，每个 token 要等上一个 |

**技巧**：让一个**固定的旧策略 π_old** 生成一次，用重要性采样比（importance sampling ratio）重新加权，就能**多次更新复用同一批生成**：

```
ρ(τ) = π_θ(τ) / π_old(τ)
J(θ) = E_{τ ~ π_old} [ ρ(τ) · R(τ) ]
```

## 5. Vanilla 方法的三大挑战（承上启下）

| # | 挑战 | 后果 | 解法 |
|---|------|------|------|
| ① | **梯度高方差** | reward 无相对基线（如 101 vs 100，都很大），更新噪声大 | baseline → **advantage** |
| ② | **缺 token 级归因** | completion 级 reward 无法区分中间哪个 token 错了 | value function（PPO）/ process supervision |
| ③ | **会跑偏** | 模型已很好，不想偏离太远；还有 reward hacking | **clipping + KL 惩罚** |

> 泰迪熊例子贯穿全讲：`泰迪在密封箱里，箱子搬去厨房，问泰迪在哪？` 模型答「泰迪爬出箱子 → 走到厨房 → 答案：厨房」。最终答案对，但"爬出箱子"是错的——vanilla 方法会把所有 token 一视同仁地奖励，包括错的步骤。

## 6. PPO（Proximal Policy Optimization）

两大改进：**① 优化 advantage 而非 reward；② 不偏离旧策略太远**（P = proximal）。

### 6.1 Advantage + Value Function（解决挑战①②）

- **value function V**：给定 prompt + 部分 completion，预测"继续采样下去，期望最终 reward 是多少"——是 **token 级**的量，作为**基线（baseline）**。
- 简单版 **advantage** = `V(到当前 token) − V(到前一个 token)`，即这个 token 相对"没有它"的增量。例：`0.95 − 0.7 = +0.25`（"box" 这个 token 贡献了 +0.25）。
- 实际更复杂（未来 token 也有间接贡献），用 **GAE**（Generalized Advantage Estimation，超纲）。
- **价值模型与策略联合训练**（两个模型，共享主干），这是 PPO 的"麻烦"来源——要额外维护一个价值模型。

### 6.2 三个策略（务必分清下标）

| 符号 | 含义 | 是否变 |
|------|------|--------|
| **π_ref** | 参考/基础模型（SFT 后的起点） | 冻结 |
| **π_old** | 生成当前这批 completions 的策略 | 每批更新 |
| **π_θ** | 当前正在更新的策略 | 训练中 |

### 6.3 两个"防跑偏"手段

- **Clipping（裁剪）**：把 ratio ρ 裁到 `[1−ε, 1+ε]`。超出范围时梯度为 0，模型失去"继续把概率推高/压低"的激励，从而不偏离 π_old 太远。
- **KL 惩罚**：在损失里加 `β·KL(π_θ ‖ π_ref)`，约束当前策略不离基础模型太远。**β 越大，越贴近 π_ref**（这个 β 就是 DPO 公式里的 β）。

> ⚠️ 读 PPO 论文两个坑：`L` 是 objective（要最大化），`r` 是 ratio（不是 reward）。

---

## 7. GRPO（Group Relative Policy Optimization）

**核心卖点：不要 value function**（省掉 PPO 最麻烦的部分）。

- 做法：一个 prompt 采样 **g 个 response**（正温度，保证多样），各自算 reward，再**组内标准化**得 advantage：

```
A_i = ( r_i − mean(r_1..r_g) ) / std(r_1..r_g)
```

- advantage 是 **completion 级**（不是 token 级）。
- 仍用 **clipping + KL 惩罚** 防跑偏。
- 只需 3 个模型：policy（训练）+ reference（冻结）+ reward model（**可选**——可验证奖励时不需要）。

### PPO vs GRPO 对比

| | PPO | GRPO |
|---|-----|------|
| advantage 怎么算 | value function（token 级） | 组内标准化（completion 级） |
| 需要 value model？ | ✅ 要（联合训练） | ❌ 不要 |
| 模型数 | policy + value + reward + ref | policy + (reward) + ref |
| token 级归因 | ✅ 有 | ❌ 无 |
| 复杂度 | 高 | 低（更流行） |

---

## 8. GRPO 的坑（读 paper 时才知道的细节）

### 8.1 Response 越训越长（经典现象）

- 现象：性能到平台后，回答长度仍持续增长。
- 根因：损失里有 `1/|o_i|`（除以 response 长度）归一化项。短 response 每个 token 的贡献被放大 → 当模型只能产出"坏答案"时，它会**偏好更长的坏答案**（长坏答案每个 token 惩罚更小）。
- 后续改进：**DAPO**（改成除以组内总 token 数）、**Dr. GRPO**（直接去掉归一化）。

### 8.2 其他两个小坑

- **除以标准差**可能引入 bias（不同复杂度输入标准差差异大）→ 可考虑去掉。
- **对称 ε**（上下界相同）不给低概率 token 被发现的机会 → 可考虑上下界用不同 ε。

## 9. On-policy Distillation（Shervin 部分，本讲后半重点）

**目标**：保留 on-policy（用模型自己的输出）+ 拿到 token 级 dense 信号 + 不多训模型。

### 9.1 思路：让 teacher 给学生每个 token 打分

学生生成 completion → teacher 对每个 token 评估"这个 token 在我（teacher）的分布里概率高吗"→ 用 reverse KL 对齐两者。

### 9.2 Reverse KL（反向 KL，关键）

- KL 不对称：`KL(P‖Q)` = "世界由 P 统治时，用 Q 近似有多糟"。
- 蒸馏时世界由 **student** 统治（on-policy），所以用 **`KL(S ‖ T)`**，不是 `KL(T ‖ S)`——叫 **reverse KL**。
- 性质：**mode-seeking**（只追 teacher 分布的峰），对"teacher 有、student 没有"的峰宽容，对"student 有、teacher 没有"的峰严厉惩罚。

### 9.3 优点

- **dense**（token 级）+ **on-policy** + **无 reward model（无可 hack）** + **计算效率高**（Thinking Machines 博客消融实验证明，同样算力下收益更高，且对参数约束友好）。

### 9.4 两个限制 + 两个变体

- 限制 ①：**需要 teacher**——frontier model 没有更强 teacher 可用。
- 限制 ②：teacher 可能不完美、覆盖不全。

- **Self-distillation（自蒸馏）**：把"完整答案 + 推理过程"直接塞进 prompt，让**同一个模型**再生成一次作为 teacher 分布——不需要外部 teacher，很巧妙。
- **Multi-teacher distillation（多教师蒸馏）**：每个领域一个专家 teacher（数学 teacher、工程 teacher…），避免遗忘和单目标偏差。
- **适用场景**：flash 系列用 on-policy distillation（快、省、防遗忘）；pro 系列用 GRPO（硬标签、费算力、更基础）。

## 10. 关键公式速记

```
目标           J(θ) = E[ R(τ) ]
Policy Gradient  ∇J = E[ R(τ) · ∇log π_θ(τ) ]     （恒等式 ∇log π = ∇π/π）
重要性采样比     ρ = π_θ(τ) / π_old(τ)
Advantage(简)   A_t = V_t − V_{t−1}
GRPO advantage  A_i = (r_i − mean(r)) / std(r)
KL 散度         KL(P‖Q) = Σ P · log(P/Q)
裁剪            clip(ρ, 1−ε, 1+ε)
```
