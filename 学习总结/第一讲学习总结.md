## 一句话主旨

模型只认数字，所以处理文本的路线是：**把文字切成 token → 把 token 变成向量 → 让向量「知道上下文」**。第一讲沿 `one-hot → word2vec → RNN → attention` 的路线，说明每一步补了上一步什么缺陷，最后落到 2017 年的 Transformer——丢掉循环结构，让每个 token 通过 Q/K/V 直接「看」全句。

> **三个转折点（老师开场的历史纵览）**：① 2010 年代是「**一个用例一个专用模型**」——情感分析、翻译、命名实体识别各训一个，主流架构是 RNN，性能尚可但没突破；② **2017**《Attention Is All You Need》引入 Transformer，关键在**可扩展（scalable）**——给更多数据/算力/参数，性能提升远超从前；③ **2022 年 11 月 ChatGPT** 发布，从产品视角把「和聊天机器人对话」变成大众习惯。到了 2026，coding agent 已是日常。

## 主线：10 个递进台阶（每个台阶都修前一个的缺陷）

| # | 台阶 | 解决了什么 | 留下的新问题 |
|---|------|-----------|-------------|
| 1 | **One-hot 编码** | 把词变成向量（只有自己那一位是 1） | 任意两个词都正交，比不出谁近谁远 |
| 2 | **余弦相似度** | 有了「比相似度」的尺子 cos = A·B/(‖A‖‖B‖) | 但 one-hot 全都 cos=0，尺子没用武之地 |
| 3 | **分词 tokenization** | 确定真正的最小单位是「子词」，不是词 | 词表多大、怎么切要权衡 |
| 4 | **嵌入 Embeddings** | 用短而密的向量替代 one-hot，近义词靠得近 | 每个词只有一个固定向量，不含上下文/词序 |
| 5 | **矩阵乘法** | 一切运算的本质：W·x + 非线性，形状要对齐 | —（这是工具，不是问题） |
| 6 | **下一个词预测器** | 把 one-hot→嵌入→打分→softmax 串成一个小网络 | 随机权重下预测是瞎猜，需要训练 |
| 7 | **Word2Vec** | 用「预测上下文」的代理任务**学出**嵌入 | 仍是每词一向量，`bank` 河岸/银行分不开 |
| 8 | **RNN** | 靠隐状态按词序读，带入上下文和顺序 | 远了就忘、串行慢、编码瓶颈 |
| 9 | **Attention** | 每个词直接「看」所有词，一步到位 | 丢掉了词序（需要位置编码补回） |
| 10 | **Q·Kᵀ 引擎** | 把 attention 落实成矩阵运算，可手算 | —（这就是 Transformer 的心脏） |

> **贯穿全文的一句话**：`Word2Vec` 给每个词一个**固定**向量（无上下文）；`RNN` 按顺序读但记不远、跑不快；`Attention` 让每个词**同时直接看所有词**，长距离、可并行、带上下文——这就是 Transformer。

## 主线补充：转写稿里讲得更细的三块

### A. 分词的三选一（台阶 3 展开）

| 方式 | 切法 | 优点 | 缺点 |
|---|---|---|---|
| **word（词级）** | 按空格切 | 简单、可解释 | 词表大；bear/bears 学不到共根；训练没见过的词 → **OOV** |
| **character（字符级）** | 按字母切 | 词表小、无 OOV、拼写鲁棒 | 序列超长（计算慢）、embedding 太抽象 |
| **subword（子词级）✅** | 从数据学出常见片段 | 折中、利用词根、序列短 | 要多训一个 tokenizer、依赖训练数据分布 |

- **BPE（Byte Pair Encoding）**是主流子词算法：从「初始字母表」出发，反复找训练语料里**最频繁的相邻 pair**、合并成新 token，直到达到目标词表大小。词从数据里「学」出来，常见搭配会被合并、序列变短。
- **现代 LLM 词表规模**：数十万量级（约 200,000），且常是多语言的。
- **特殊 token**：`[UNK]`（未知词）、`BOS`（序列开始，生成时的启动符）、`EOS`（序列结束，生成停止的信号）、`padding`（把序列补到等长，硬件喜欢同维度），以及现代对话里的 user/assistant 等。

### B. Word2Vec 的两个变体（台阶 7 展开）

- **CBOW（Continuous Bag-of-Words）**：用上下文词预测中间的词。
- **skip-gram**：用中心词预测周围的词。
- 两者都是「**代理任务（proxy task）**」——不是真要预测，而是借这个任务**顺带把中间的隐层表示学成有意义的词向量**。学完后会发现：`Paris − France + Germany ≈ Berlin` 这类关系自动浮现。
- **明确的三个局限**（老师逐条列的）：① **一词多义**——`bank`（河岸/银行）在不同句子得到同一个向量；② **词序无关**——`child hugs bear` 和 `bear hugs child` 得到相同 embedding；③ 训练没见过的词没有表示。

## 核心机制精讲

### 1. Q / K / V 三个角色（检索类比）

- **Query（查询）**：当前词发问——「我要找和谁相关？」
- **Key（键）**：每个词的标签——「我是谁、在说什么」
- **Value（值）**：每个词真正交出的内容——「我有什么」

流程：`Q 去和每个 K 打分 → softmax 成权重 → 按权重加权求和 V`。
**自注意力**：Q/K/V 都来自同一句话（每个词既当查询、又当键、又当值），让一句话内部互相理解。

### 2. 注意力公式四步（论文命根子）

```
Attention(Q,K,V) = softmax( Q·Kᵀ / √d_k ) · V
```

1. `Q·Kᵀ` → (n,n) 相关度方阵，第 i 行第 j 列 = 词 i 对词 j 的关注度
2. `÷ √d_k` → 缩放，防止点积过大把 softmax 推入饱和区（梯度消失）
3. `softmax` → 每行变成和为 1 的权重
4. `·V` → 按权重混合，得到每个词「带上下文」的新向量

### 3. 多头注意力（维度账，记死一条）

**`d_k = d_model / h`**（论文 512 ÷ 8 = 64）：

```
X(n,512) → 每头投影 W_Q/W_K/W_V(512,64) → Q/K/V(n,64)
        → scores(n,n) → softmax → head_i(n,64)
        → Concat(8头)(n,512) → W_O(512,512) → 输出(n,512)
```

分 8 头 = 用同样的钱买 8 个不同视角（语法/语义/指代/位置……），计算量不涨。

### 4. 掩码：把「未来」设成 −∞

Decoder 自回归生成，预测第 t 个词时只能看前 t−1 个。做法是在 **softmax 之前**给未来位置加 **−∞**（不是 0），`e^(−∞)=0` 让未来权重**精确归零**。结构是**下三角矩阵（因果掩码 causal mask）**。仅自注意力用，交叉注意力不用。

### 5. 位置编码：注意力天生「路痴」

注意力对词序不敏感（打乱词序输出不变），但「狗咬人」≠「人咬狗」。解法：**词向量 + 位置向量 = 输入**。论文用 sin/cos 固定式：`PE(pos,2i)=sin(pos/10000^(2i/d))`，偶数维 sin、奇数维 cos。位置向量只跟「排第几」有关，跟词本身无关。

两种做法：
- **learned（学出来）**：每个位置学一个向量。自然，但**缺陷是超长位置没学过**——训练只到 500 个位置，遇到 1000 token 的输入就「没辙」。
- **sinusoidal（写死）**：不同频率的 sin/cos 公式直接算，**任意长度都能表示**。

> 🕐 **为什么用「不同频率」？——手表指针类比（老师原话）**：手表有时针、分针、秒针，三根针各自以**不同频率**转动（时针最慢=粗略定位时段，秒针最快=最精确），**三针合在一起才知道确切时间（如 4:49）**。位置编码同理：用一组**从低频到高频**的 sin/cos，每个维度就是一根「不同转速的指针」，合在一个向量里，模型就能判断「精确在第几个位置」。附带一个好处：**相邻位置编码相似、远的相异**。

### 6. Encoder–Decoder 架构（原论文为翻译设计）

| 位置 | query 来自 | key/value 来自 | 能看到 |
|------|-----------|---------------|--------|
| encoder 自注意力 | 源句 | 源句 | 源句全部 token |
| decoder 掩码自注意力 | 已生成译文 | 已生成译文 | 自己和左边 |
| decoder 交叉注意力 | decoder | encoder 输出 | 源句全部 token |

### 7. 原版 Transformer 的四个「技巧」（tricks，转写稿补齐）

除注意力 + FFN 两个主角外，原版还有四个让训练更好的配件：

| 技巧 | 作用 |
|---|---|
| **残差连接（residual connection）** | 输出 = `f(x) + x`，像「**修改** x」而非「完全重写 x」，帮助反向传播、深层网络学得动 |
| **Layer Normalization** | 归一化每层的激活，帮助收敛 |
| **dropout** | 训练时按概率随机丢弃一些单元，防止过拟合、提升泛化 |
| **label smoothing** | 把「100% 预测 day」软化成「90% day + 10% 其他」——因为语言有多种合理续写；提升 BLEU（但会拉差 perplexity，见自测题 5） |

> **若只留两样，留什么？**（课堂问答的「精髓」）**注意力层 + 前馈层（FFN）**。其中 **FFN 容纳了绝大部分参数**、是「学习发生的地方」；其余组件都是帮助更好学习的技巧，外加数据质量。这也是后面几讲「砍掉 encoder、换掉各部件」时，始终保留下来的两样。

## 关键数字速记（面试够用）

- 基础 Transformer：**N=6 层**、**d_model=512**、**h=8 头**、每头 **d_k=d_v=64**、FFN 隐层 2048、约 **6500 万参数**
- 投影矩阵维度：`W_Q(d_model,d_q)`、`W_K(d_model,d_k)`、`W_V(d_model,d_v)`；**约束 `d_q = d_k`**（Q·Kᵀ 点积要求同维），`W_O` 把 `h·d_v` 拼回 `d_model`
- 相对 RNN/CNN 三大贡献：**全程可并行**、**任意两词 O(1) 直连**、**注意力权重可解释**
- 源头论文：*Attention Is All You Need*（Vaswani et al., 2017，arXiv:1706.03762），被引 25w+

## 一个手算例子：`bank` 怎么吸收 `river` 的含义

句子 "river bank"（河岸）里，`bank` 的词向量原本是它自己的 value `[0,4]`。经过 Q·Kᵀ 打分后，`bank` 的 query `[2,0]` 与 `river` 的 key `[2,0]` 同向 → 高分 → softmax 后 `bank` 把 **94%** 注意力给 `river` → 输出 `[3.78, 0.22]`，几乎全是 river 的贡献。

→ **这正是 Word2Vec 做不到的事**：`bank` 的向量随上下文重算，「河岸」和「银行」得到不同表示。**上下文被「烤」进了向量里。**

## 三个常考辨析

1. **自注意力** vs **掩码自注意力** vs **交叉注意力**：QKV 全来自同一序列 / 遮未来 / Q 来自 decoder、KV 来自 encoder。
2. **掩码为什么是 −∞ 不是 0**：softmax 前加 0 没用（e⁰=1），只有 −∞ 让 e^(−∞)=0 把未来「遮死」。
3. **embedding model vs LLM**：前者 `文本→向量`（检索/聚类/RAG），后者 `文本/上下文→文本`（生成）；RAG 里前者做召回、后者做生成。

## 自测题（检验是否真懂）

1. QKᵀ 是 n×n 矩阵，序列长度翻倍，注意力的计算量/显存怎么变？这如何影响「子词 vs 字符级」的取舍？
2. 去掉位置编码、打乱词序，encoder 输出会怎样变化？
3. 现在的 LLM 大多只有 decoder（没有 encoder 和交叉注意力），那「提示词」放在哪里、由哪种注意力读？
4. 训练时 decoder 看参考译文，推理时看自己生成的 token——这种不一致会带来什么问题？
5. 为什么 label smoothing 让 BLEU 变好、却让 perplexity 变差？

## 动手验证

`next_word_predictor.py`（SutirthaSaha 提供）用 6 个词跑通了整条链路：`"cute" → one-hot [1,0,0,0,0,0] → ×W1 → embedding [0.51,0.95] → ×W2 → 6 个 score → softmax → argmax 预测下一个词`。随机权重下预测是瞎猜（`cute → fast`），**训练就是反复微调 W1/W2 直到预测合理**——这就是 Word2Vec 和一切 LLM 预训练的原型。
