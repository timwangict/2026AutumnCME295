## 一句话总结

**训练 LLM 不是"一步到位"，而是一条流水线：先用海量互联网文本做「预训练」学会语言本身 → 再用高质量数据「中期训练」补领域知识、拉长上下文 → 用问答对「监督微调」学会当助手 → 用人类偏好「RLHF/DPO」学会语气与价值观 → 最后用「可验证奖励 + 强化学习」逼出推理能力。** 贯穿全程的目标函数几乎始终是"预测下一个 token"，变的只是数据、损失的位置、和奖励信号。

## 全局框架：训练的五个阶段

| 阶段 | 目标 | 数据规模 | 核心变化 |
|------|------|----------|----------|
| ① 预训练 Pretraining | 学会语言本身 | 数万亿~数十万亿 token | 互联网全量文本，next-token prediction |
| ② 中期训练 Midtraining | 补领域知识 + 拉长上下文 | 高质量、长文本 | 代码/数学/长文档，RoPE 频率插值 |
| ③ 监督微调 SFT | 从"续写"变成"回答" | 数百万（少几个数量级） | instruction-response 对，损失只算答案 |
| ④ 偏好对齐 RLHF/DPO | 学会"什么不该做" + 语气 | 偏好对比对 | 奖励模型 + 强化学习 / 直接偏好优化 |
| ⑤ 推理训练 Reasoning | 学会"思考后再答" | 可验证的题目 | 可验证奖励 + GRPO 强化学习 |

## ① 预训练 Pretraining：学语言

### 思路转变：从"一用例一模型"到"迁移学习"

- **15 年前**：垃圾邮件检测一个模型、情感分析一个模型、翻译一个模型……各自为战。
- **现在**：一次性大规模预训练，学"语言"这个通用能力，再针对具体用例微调。这叫 **迁移学习（transfer learning）**。

### 训练目标：预测下一个 token（next-token prediction）

- 输入一段文本，让模型逐 token 预测下一个，循环往复。
- **可并行**：因为第一讲讲的**掩码自注意力（masked self-attention）**，每个位置只看自己及之前，所以不用串行逐个算，可以一次性喂整段、同时预测所有位置——本质是一次巨大的矩阵乘法。
- **teacher-forcing（教师强制）**：不管模型自己预测对错，下一步的输入永远用"正确答案"。这带来一个隐患——**训练/推理不一致**（训练时喂真值，推理时喂自己生成的值），后续有方法缓解。

### 损失函数：交叉熵（cross-entropy loss）——从第一性原理推导

> 别背公式，记住推导思路：**找到参数 θ，让模型"看到训练数据"的概率最大化。**

1. 整段序列的概率 = 逐 token 条件概率连乘：`p(x1…xn) = ∏ p_θ(x_t | x_<t)`
2. **问题**：每个概率都在 0~1 之间，连乘会**急速趋近 0**，数值下溢 → 取 **log**，把连乘变连加（`log 的性质`）
3. 机器学习习惯**最小化** → 取负号（minimize `-log`）
4. 除以 token 数 T，消除序列长度对损失尺度的影响

最终：`L(θ) = -(1/T) Σ_t log p_θ(x_t | x_<t)`

**BPB（Bits Per Byte，每字节比特数）**：交叉熵的绝对值依赖 tokenizer（分词方式不同，数值不可比）。BPB 把损失转成"每个字节多少 bit"，跨 tokenizer 可比：`BPB = L × (T/B) × (1/log2)`。B 是字节数。

### 数据：从哪来、怎么筛

- 来源：互联网网页（Common Crawl）、代码仓库（GitHub）、数学、科学、权威百科（Wikipedia）……
- 规模：**数万亿 token**，近期甚至数十万亿（GLM-5 用了 30 万亿 token）。
- **重复训练**：数据受限时，同一批数据最多重复训练 **4 次**仍有收益。
- **数据配比**：训多个小模型试不同混合比例，反推最优配比（DataComp-LM 等论文）。
- **知识截止日期（knowledge cutoff）**：模型知识固定在训练数据截至的某天（如 GPT-6 Astra 到 2026-04-30）。之后发生的事它不知道，需要后续手段（RAG/联网等）弥补。

## ② 中期训练 Midtraining + 长上下文

- **目的**：预训练通常只在**几千 token 的短序列**上做（省算力），但真实需求是几万~几十万 token。中期训练用高质量、长文本数据补上这块。
- **长上下文的两个难点**：
  1. 自注意力复杂度 **O(n²)**——序列翻倍，算力翻四倍；
  2. **难找"长程依赖"的训练数据**——需要"答案依赖很远处信息"的样本，天然稀少。
- **RoPE 扩展（YaRN 等）**：RoPE 没有可学习参数，理论上可直接用，但模型**没见过的旋转角度会"懵"**。做法是**插值频率**，让长距离的位置差落在短上下文训练时见过的频率范围内。
- **课程学习（curriculum learning）**：先短（如 4K）后长（如 128K~200K），循序渐进。
- GLM-5 的中期训练用 **best-fit packing**：尽量让文档不被切断地打包进上下文。

## ③ 监督微调 SFT：学会当助手

### 为什么要 SFT

预训练完的模型只会"续写"：你问"泰迪熊能放洗衣机吗？"，它给你接一段百科式的说明——**不是回答，是自动补全**。SFT 用 `指令→回答` 对，把"续写"拧成"回答"。

### 关键点

- **目标函数仍是 next-token prediction**，但损失**只算答案部分，不算输入**（输入是给定的，不惩罚它）。
- **数据量**：比预训练少几个数量级——专用任务几百~几千条，通用助手数百万条。
- **挑战**：SFT 数据质量要求极高（模型会严格模仿）；数据分布偏差会让模型"有偏见"。

### LoRA：低秩适配（省参数的微调）

- 动机：模型动辄百亿~千亿参数，微调真的需要动所有参数吗？——通常不需要，因为"你离目标已经很近了"。
- 做法：把权重拆成 `W = W0 + BA`，W0 是冻结的预训练权重，B、A 是**低秩小矩阵**，只训练它们。
- 好处：**参数暴减**、**存储省**（多个任务只存各自的小 B、A，共享同一份 W0）。
- 位置：最初只在注意力层做，现在**推荐也在 FFN 层做**（因为参数大头在 FFN）。

## ④ 偏好对齐：RLHF 与 DPO

### 动机

SFT 只告诉模型"做什么"，没说"**不做什么**"。你问"给泰迪熊想个活动"，它可能答"别跟泰迪熊玩了"——是回答，但不是你想要的。需要注入"偏好"。

### 偏好数据怎么收集

- **pointwise**：对单个回答打绝对分（人类难）。
- **pairwise**：两个回答比谁好（人类容易，最常用）。
- **listwise**：一串回答排序。

### RLHF：两步走

**Step 1 — 奖励模型（reward modeling）**：训练一个模型，对"给定 prompt 的回答"打分。

- 用 **Bradley-Terry 公式**：`P(y_i 优于 y_j) = sigmoid(r_i - r_j)`，其中 `sigmoid(x) = 1/(1+e^(-x))`。
- 损失：`min -log σ(r(win) - r(lose))`——和交叉熵同款推导（先想最大化，再取 log、取负）。

**Step 2 — 强化学习（RL）**：用冻结的奖励模型指导 LLM 更新权重。

- 目标 = **最大化奖励 + 不要偏离参考模型太远**（加 KL 惩罚，因为模型已经够好，且奖励模型不完美）。
- **reward hacking（奖励黑客）**：模型学会钻奖励模型的空子，去讨好"不完美"的奖励模型，而非真正变好。

### DPO：直接偏好优化

- 痛点：RLHF 要训奖励模型 + 做 RL，复杂、超参敏感。
- DPO 把问题改写成**监督式**：一个损失函数，直接"抬高好答案概率、压低坏答案概率"，**不需要奖励模型**。
- 代价：DPO 是 **off-policy**（用固定数据，不是模型自己生成的输出），RLHF 是 **on-policy**（用模型实际输出）。

### 效果

同一句"泰迪熊能放洗衣机吗"，从生硬的 "No" 变成友善的："It's better not to. Your teddy could get hurt! A gentle hand wash is safer."

## ⑤ 推理训练：让模型"思考后再答"

### 什么是推理

- 非推理题："这门课代码是什么？"——知道就知道。
- 推理题："你的熊 2020 年出生，现在几岁？"——需要算"现在哪年、差多少年"。

### 时间线

- **2024.09** OpenAI 首次公布用该技术提升数学/代码表现。
- **2025.01 DeepSeek-R1**：第一个开源权重的推理模型，讲清了"怎么训练"。
- **今天**：几乎所有模型都是推理模型，推理链默认**隐藏**。

### 为什么隐藏推理链

1. **安全**：推理链包含大量用户与对话信息，不该暴露；
2. **防蒸馏**：高质量推理链能提升别人模型的性能，所以藏着不给看。
> 提醒：推理链也算 output token，**你会为看不见的思考部分付费**。

### 训练方法：可验证奖励 + GRPO

- 关键洞察：数学/代码题**答案对错可判定**（跑测试用例、比对标准答案），不需要奖励模型——这叫 **可验证奖励（verifiable rewards）**。
- **GRPO（Group Relative Policy Optimization，分组相对策略优化）**：同一 prompt 让模型生成多个回答，算每个回答相对同组的"优势"，好的多做、差的少做，同时仍用参考模型约束不跑偏。（数学细节第 4 讲再讲）

### 两个限制 & 新趋势

- **稀疏奖励**：只能对整个输出打一个对/错，没有 token 级信号。
- **on-policy distillation（在线策略蒸馏）**：让一个 teacher 模型对生成的**每个 token** 打分，学生模型对齐 teacher——**既是 on-policy（用学生自己的生成）又是 dense（token 级信号）**。变体有"自蒸馏"（同一个模型，但告诉它答案）。
- 已被多数前沿开源模型采用，常配合"数学 teacher + 工程 teacher"等多专家蒸馏。

## ⑥ 实践案例：GLM-5（Shervin 部分）

拿 GLM-5 技术报告逐阶段对照：

- **预训练数据管线**：Common Crawl（启发式过滤，**最终只保留约 1%**）+ 权威网站 + 代码 + 数学。数据先 chunk 再拼接填满上下文。
- **model collapse（模型崩溃）**：现在互联网已混入大量 AI 生成内容。用 AI 产出训练 AI，分布会逐代退化（长尾细节丢失、偏好被放大）——所以数据筛选越来越重要。
- **中期训练**：长文本（PR + code diff、整本书），best-fit packing。
- **SFT**：注入推理 + tool calls 数据，出现 **think tokens（思考 token）**——夹在输出里、不显示给你看的"草稿区"。
- **RL 三部分**：reasoning RL（可验证的数学题）/ agentic RL（放进 harness 跑测试）/ general RL（正确性、情商、任务质量等软维度）。
- **on-policy cross-stage distillation（跨阶段蒸馏）**：最后对 SFT 后的、第一轮 RL 后的 checkpoint 做蒸馏，**防止前面的能力丢失**。

## 附录：log、sin、cos 基础（这一讲用到的数学）

### 一、log（对数）：为什么机器学习里到处都是它

**一句话结论：log 是"乘法的克星"——它把「连乘」变成「连加」，是 ML 里最常用的"稳定剂"和"降维工具"。**

**① 它是什么**
`log_a(b) = c` 的意思是 **`a^c = b`**（a 的几次方等于 b）。即 log 是"求幂的逆运算"。
例：`log_2(8) = 3`，因为 `2³ = 8`。

**② 最关键的一条性质（本讲交叉熵推导的核心）**
```
log(x · y) = log(x) + log(y)
```
所以一堆数连乘，取 log 后变成一堆数相加：
```
log(0.5 × 0.5 × 0.5) = log0.5 + log0.5 + log0.5
```

**③ 为什么交叉熵里要取 log（两个原因）**
1. **数值稳定**：概率都是 0~1 之间的小数，成百上千个连乘会**急速趋近 0**，计算机里直接下溢成 0，没法算。取 log 后变成"一串负数的求和"，稳稳当当。
2. **单调性**：log 是单调递增函数，`log(a) > log(b)` ⟺ `a > b`。所以"最大化 log P"和"最大化 P"的**最优解完全一样**，取 log 不改变答案，只让计算变好做。

**④ 自然对数 ln 和 e**
- ML 里说 log 默认就是 **ln（自然对数）**，底是 **e ≈ 2.71828**（自然常数，一个像 π 一样神奇的无理数）。
- **为什么 1/log(2) 会出现（BPB）**：换底公式 `log_2(x) = ln(x) / ln(2)`。交叉熵默认是 ln（单位"奈特"），乘上 `1/ln(2)` 就换算成以 2 为底（单位"比特 bit"）——所以叫"每字节比特数"。

**⑤ 一句话记忆**
> 连乘会下溢 → 取 log 变连加；log 单调 → 最优解不变；除以 ln2 → 换算成比特。

---

### 二、sin、cos（正弦、余弦）：从"单位圆"到"位置编码"和"旋转"

**一句话结论：sin 和 cos 是"圆周运动"在两个坐标轴上的投影，天生自带「周期性」和「旋转」——这正是位置编码（第 1 讲）和 RoPE（第 2 讲）要借用的东西。**

**① 用单位圆理解（最直观）**
画一个半径为 1 的圆（单位圆）。一个角度 θ 对应圆周上一点，这个点的：
- **横坐标 = cos θ**
- **纵坐标 = sin θ**

所以 sin/cos 就是"转圈"这件事的两种描述方式。

**② 周期性（最关键的性质）**
```
sin(θ + 2π) = sin θ     cos(θ + 2π) = cos θ
```
转一整圈（2π 弧度 = 360°）回到原值。sin/cos 的值永远在 **[-1, 1]** 之间来回震荡。

**③ 在位置编码里（第 1 讲）**
原版 Transformer 用 `PE(pos, 2i) = sin(pos/10000^(2i/d))`、`PE(pos, 2i+1) = cos(...)`：
- 不同维度 i 用**不同频率**（周期不同），像钟表的时针/分针/秒针各转各的；
- 每个位置 pos 得到一串**独一无二的"波纹指纹"**；
- 因为 sin/cos 有周期性 + 加法公式，模型能推演出"谁在谁后面第几位"（相对位置）。

**④ 在 RoPE 里（第 2 讲 + 本讲长上下文）**
RoPE 不"加"位置，而是把位置信息**旋**进向量。旋转用的矩阵就是：
```
[ cos θ   -sin θ ]
[ sin θ    cos θ ]
```
本质还是 sin/cos——把向量转过一个角度 θ，θ 由位置决定。这也是为什么本讲讲"RoPE 频率插值"（YaRN）时，改的其实是这些 sin/cos 的频率。

**⑤ 为什么选 sin/cos 而不是随机数**
1. **零学习成本**：公式直接算，不用训练；
2. **位置唯一且连续**：每个位置编码不同，但相邻位置很接近；
3. **有周期性**：能表达相对位置。

**⑥ 一句话记忆**
> 单位圆上转一圈，横 cos 纵 sin；周期性 + 旋转，正好用来标"第几位"和"转多少角度"。

### 三、顺带：e 和 sigmoid（转写稿里也露了面）

- **e ≈ 2.718**：自然常数，ln 的底，描述"连续增长"的极限（像"利滚利"滚到极限）。
- **sigmoid(x) = 1/(1+e^(-x))**：把任意实数压到 **(0,1)** 区间，正好当"概率"。奖励模型里 `P(y_i ≻ y_j) = sigmoid(r_i - r_j)`——两个回答奖励差越大，胜出的概率越接近 1。
